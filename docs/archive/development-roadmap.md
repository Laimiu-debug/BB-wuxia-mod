# 《战场兄弟》武侠 Mod 开发路线

第一段可玩战役要让两个领队从同样三名侠客和同一册剑谱出发，凭结交的人、所走的路和各人深修的功法，养出两支都值得玩到后期的队伍。

这里的后端指随 Mod 在游戏里运行的战役规则、战斗判定和存档。先用原版或占位素材跑通一段江湖，再分批扩充正式内容和美术。自有 UI 从主菜单起步。每套玩法第一次进入游戏时，就配上可操作的简版界面。下列各阶段均为拟议工作。具体任务见[开发待办清单](development-todo.md)。

## 开发顺序

| 阶段 | 主要产物 | 进入下一阶段时应能看到什么 |
| --- | --- | --- |
| 1．游戏接入与武侠主菜单草版 | 确定 Windows 游戏、DLC、汉化和框架的测试组合，跑通 Mod 加载、打包和日志。随即用临时题签、底色和重新编排的入口做第一版主菜单。 | 冷启动游戏后，玩家在第一个可操作的主菜单就认得这是武侠 Mod。能开新局、读已有测试档、进设置、返回或退出。 |
| 2．战役数据与存档 | 给侠客、师门、势力、功法、物品和差事稳定的编号。分别记录一个人跟谁学过、为谁办事、当前与谁同行。建立规则向 UI 提供数据、接收操作的途径。 | 将一名有师承、替别家办事的测试侠客放进队伍。保存退出后再载入，他的关系、物品和所学仍对应本人。另开一局能得到独立的江湖。 |
| 3．门派、组队与学艺 | 做招募与去留、势力引荐、已有师父与秘籍、跨派求学、个人专修。接入首版起源页、侠客名册和修习簿。 | 同门能选不同方向，不同势力出身的人能因共同承诺同行。玩家亲自决定谁学哪门功夫，能查到来路、取舍与已学本领。 |
| 4．战斗、敌方行为与历练 | 接入行动点、替代疲劳的内力、兵器基础招式、师门武学、内功与身法。让实战发生的事回写修习簿。战斗 HUD 同步显示出招机会与团队配合。 | 同一组对手能检验剑客主攻和多人轮换两种打法。敌手能应对各自看得见的行动。战后能认出谁做成了什么、谁因此可以再求教。 |
| 5．江湖势力、差事与首段可玩战役 | 接通组织来往、委托、货物归属、酬金、伤养和一次百工配药，让地方消息带来下一次引荐。先用原版城镇、战场和少量候选组织承载这些规则。 | 能从武侠主菜单开局，结伴、学艺、办差、交手、带着结果回来，再获得不同的邀约。玩家让别队接手的差事也能在本局产生下文。 |
| 6．整套自有 UI | 将前五阶段的简版页面做成统一的游戏界面。补齐起源与读档、侠客与武学、战斗和战后、江湖舆图与差事、行囊与伤养。 | 玩家从启动到办完下一趟差事，都能通过正式的页面导航完成。读得懂队友的不同价值，也能追溯一门武学或一段人情的来路。 |
| 7．人物、兵器、场景与门派内容分批替换 | 按下方批次替换占位资源。玩法通过验证的门派，以师父、武学、对手、相关人情与差事为一组加入，并配对应美术。 | 同一份战役存档从占位版换到正式资源后，仍能认回原来的同伴、装备、师承和差事。新增门派能给已有队伍带来新的取舍。 |
| 8．完整战役、平衡与发布准备 | 扩起源、势力活动、地域、异兽、奇遇、名器、百工和单局目标。结合长战役试玩调整招募、修为、经济与势力变化，验证安装、升级和中文显示。 | 几位玩家能以不同阵容完成同一项后期挑战，并说清各自愿意培养谁、舍弃什么。能从干净安装走完完整战役，明确发布包的依赖与存档适用范围。 |

前五阶段按表中顺序接通。界面设计可以提前，页面上的操作随对应规则接入。第 5 阶段的同局对照达到预期以后，正式 UI 与首批人物、兵器样稿可以并行。依赖最终界面尺寸或角色图层的素材，等对应版式、锚点确定后再批量制作。

## 第一段战役怎样判断好不好玩

建议用残剑门弟子、老镖师、黑风寨旧人和一册《回锋剑谱》做同一起点，保留出发前的存档供两条路线分别试玩。世界里先放两个可求教的师承、两个有不同利益的组织。首轮数量只用于控制样板规模。

1. **让领队亲自选路。** 一次选择赴会论剑，给弟子寻找争先的剑路。另一次先替旧友履约，通过镖局的引荐学接应之法。两次开局的人、秘籍和可遇见的机会相同。
2. **让两队面对同一场会武。** 一队让伙伴为剑客创造决胜机会。另一队让几名侠客轮流承担主攻与接应。战后分别记下参战者真正用过什么本领，以及接下来值得向谁请教。
3. **把同一位名门剑客放到两队面前。** 两队都能考虑邀请他。试着把老镖师换下，观察队伍得到什么、失去什么。若换上高资质剑客对两队都是全面提升，就回到资质、专修代价和伙伴配合三处调整，再扩门派和秘籍数量。

药镖另验世界是否会自己往前走。用同一批货分别走到送达、失镖后先救人、交由别人承运三种结果。回镇打听时，药铺的供货、知情人的消息和后续委托应各有依据。把两段放在一起，才能同时检验“队伍怎样赢”和“这趟江湖改变了什么”。

## 自有 UI 从哪里开始

| 首次接入 | 玩家会看到什么 | 正式版重点 |
| --- | --- | --- |
| 阶段 1 | 武侠主菜单题签、临时背景与入口，随后能进入起源选择和读档。 | 确立暗色明末写实的视觉方向、中文字体层级和菜单用语。分别实测主菜单、加载画面以及更早的引擎启动画面可修改到哪里。 |
| 阶段 3 | 起源页说明初始承诺与人手。侠客名册能看出身、师承、立场和职责。修习簿能选择求教对象、研读秘籍、查看深修方向。 | 招募时看得懂“此人和现在这队怎么配”。能在队伍视图与个人经历之间往返。 |
| 阶段 4 | 战斗 HUD 展示行动点、内力、敌我意图、可接手的伙伴与招式后果。战后能看到伤势、履历与新的修习机会。 | 紧要信息在棋盘旁就读得到。简要提示、详细说明和战后复盘使用同一套规则。 |
| 阶段 5–6 | 舆图、城镇、势力往来、委托、行囊、百工与调养陆续接上真实战役数据。 | 统一导航、提示、返回操作、存读档和常用分辨率下的中文可读性。阶段 8 的隐退或其他结局沿这套导航接入。 |

## 正式美术分批替换

| 批次 | 替换内容 | 在游戏里怎么验 |
| --- | --- | --- |
| 入口与图标 | 主菜单正式题图、题签、共用窗口和按钮素材，首批功法、状态及物品图标。 | 从主菜单进入战斗，中文、选中状态、禁用状态和图标含义在实际尺寸下可辨。 |
| 人物与兵器 | 先用一名侠客打通头面、发饰、衣甲、持械的图层，再配一件短兵和一件长兵。一起验人物常态、受伤与倒地，以及背包图和手持图。 | 同一人换装、换武器和受伤后仍对齐。对方是什么兵器、同伴在担任什么职责，在战场上一眼看得出。通过后再扩各门派。 |
| 战场与城镇 | 先完成一个可交手的场景、一处可办差的城镇。随后扩道路、地形、建筑、设施和相关事件插画。 | 在同一趟差事里进出城镇与战场，能读清高低、遮挡、可走地块与可交互位置。 |
| 江湖舆图与地域 | 换地图上的队伍、旗帜、城镇、门派驻地和地域地貌，随场景补环境音与音乐。 | 已知据点、不同势力和路线容易辨认，换美术后任务仍能抵达原目标。固定神州方位属于地图生成的另一次决策。 |

阶段 2 就给资源定好引用方式。换图、改题签、更新场景外观都能沿用原人物与物品编号。每批先在整段游戏流程里看样稿，再决定同类资源的产量。

## 在对应阶段定下的选择

- **阶段 1** 核实目标游戏版本、DLC、中文环境以及 Modern Hooks、MSU 等依赖组合。若用动态专长框架承载武学，再验证其配套依赖、学习入口和存档行为。
- **阶段 3–4** 选择首轮师承与势力样本，试定专修的取舍和防御方式。架势可先用短时破绽比较两种打法，独立架势条待试玩后定。
- **阶段 5** 决定领队身亡后的队伍去向、玩家与起源组织的权限，以及哪些人物和事件由江湖持续追踪。这些决定会影响后续战役和存档。
- **阶段 7–8** 根据首批实机样稿定美术规模，再定后期起源数量、固定地域范围和完整战役目标。

当前范围以单局江湖领队、既有门派与秘籍、按人修习、内力替代疲劳为基础。老技术稿中的独立内力条和耗气累计修为已被后续讨论调整，拆任务时使用现行口径。[设计决议](https://app.notion.com/p/41b5946e369881da87e3de593f59efe6) · [项目讨论纪要](project-discussion-log.md) · [武侠百科](../武侠百科.html)
