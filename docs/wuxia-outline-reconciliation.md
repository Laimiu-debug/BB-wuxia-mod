# 六模块设计大纲与现有设计方案的对照

对照对象：用户 2026-11-17 给出的六模块大纲（含十个门派的补充），和 `/cursor/stores/bc-b8a1a0a3-bf95-43a8-8cbc-f15d2d16db06/docs/wuxia-mod-design.md`（下称"方案"）。

方案本身没有改动。下面第 2 节的三个分歧定下来之后，方案的第 2、4、7 节要重写。

标记：**已核实** = 这次在源码里查过；**凭记忆** = 没查，动手前要确认。

## 1. 大纲里要更正的事实

| 大纲的说法 | 实际情况 |
| --- | --- |
| "`Modding Script Hooks` (MSU)" | 这是两个东西。Modding Script Hooks 是 Adam 的旧 hook 框架（mod_hooks）；MSU 是 Modding Standards & Utilities。我们用的是 Modern Hooks + MSU |
| 参考 Legends 的动态天赋树源码 | Legends 的树不是 DPF，而且它仍用旧的 mod_hooks 注册（已核实）。之前定的是 DPF，范例是 Reforged。Legends 可以读，不能照搬 |
| 参考 Legends 的分层纸娃娃 | 原版人物本来就是分层的。Legends 的分层护甲是另一套很大的系统，画粗麻劲装和斗笠用不着它 |
| 医女、峨眉、"不收女弟子" | 原版没有女性角色的身体和头部素材（已核实，原版脚本里没有任何 female 相关内容；Legends 有）。要女性角色就要新画一整套头、发型、身体，各带受伤和倒地版本 |
| 丐帮敌人数量是普通队伍的 2–3 倍 | 单场战斗人数太多会让回合很长，部署区和地图大小也有限。上限是多少我没有实测 |

## 2. 三个必须先定的分歧

### 2.1 内力：替代疲劳，还是独立资源

之前商定的架构是"内力作为独立资源"，方案第 2 节按这个写的。大纲写的是"内力替代疲劳值"。两者只能选一个。

| | A：独立资源（方案现状） | B：疲劳换皮成内力（大纲） |
| --- | --- | --- |
| 实现 | 新数据、新界面条、在技能基类接入消耗、存档 | 改名字和图标，条的显示方向反过来（原版是累积，内力是消耗） |
| 调息 | 新技能 | 原版已有 Recover：9 行动点，疲劳减半（已核实） |
| 敌人 AI | 只懂"够不够用" | 原版 AI 本来就管理疲劳 |
| 吸星、化功 | 要自己写 | 给目标加疲劳即可 |
| 没练内功的人 | 没有内力条，和原版一样 | 人人都有，内功只影响上限和回复 |
| 护甲 | 无关 | 原版重甲会压低疲劳上限，变成"重甲碍内息"，和明末轻装的基调合 |
| 代价 | 再加架势条就是两条新条，界面放不下 | 移动和普通攻击也耗内力；"耐力"和"爆发"合成一个资源；汉化包里所有写"疲劳"的文本要覆盖 |

建议选 B，前提是要做架势条。理由：大纲同时要内力和架势两条新资源，战斗界面只腾得出一个位置（Reforged 加新属性时是顶掉了士气条）。内力用疲劳的位置，架势用士气的位置，刚好。选 B 后方案第 2 节大幅简化，心法层数改为调整疲劳上限和每回合恢复量（原版属性 `FatigueRecoveryRate` 默认 15，已核实）。

### 2.2 架势条

可行，是全新的一条资源。接入点都在原版技能事件里（已核实存在）：`onBeingAttacked`、`onMissed`、`onBeforeDamageReceived`、`onDamageReceived`。

- "破绽时必定暴击"：BB 没有暴击，只有爆头的伤害加成。用伤害倍率加上降低受伤门槛实现，原版属性里有 `ThresholdToReceiveInjuryMult`（已核实）。
- 点穴、断筋、内伤：做成自定义伤病，原版伤病体系可扩展。
- 代码不是主要风险，数值是。原版所有武器和敌人的数值都建立在"伤害对护甲"上。护甲退居次要后，每把武器、每个敌人都要重新定数值。
- 原版 AI 不认识架势，不会主动集火破绽目标，要在目标评分里补。怎么补我没查。
- 如果做架势，建议重新考虑引入 Modular Vanilla：它把命中和受伤的大函数拆开了，"格挡扣架势而不扣血"写起来干净得多。

需要定：架势是叠在护甲之上（官兵仍靠甲，江湖人靠架势），还是基本取代护甲。前者改动小。

### 2.3 是否全面替换原版世界

大纲的美术基调（暗黑明末水墨）、朝廷、十个门派、中国风地貌，合起来等于回答了方案第 8 节第 1 问：全面替换。这是工作量最大的一个决定，请明确确认。

如果确认，建议把武侠势力套在原版势力类上，而不是从零写。原版有 50 个契约脚本（已核实），都和势力类型绑定，继承原版势力类才能复用。对应关系是设计建议，细节未核实：

| 武侠势力 | 复用的原版势力或机制 |
| --- | --- |
| 黑风寨 | 强盗势力 |
| 朝廷、靖夜司 | 贵族家族（正规军兵种、巡逻、战争契约） |
| 世家 | 城邦或贵族家族 |
| 塞外密宗 | 野蛮人 + 兽人的狂战士定位；"塞外入侵"套绿皮入侵危机 |
| 唐门 | 地精的定位：远程、毒、网、游击 |
| 五毒教 | 驯兽师和战犬机制（已核实存在）+ 原版毒药 |
| 魔教 | 亡灵危机的模板 |
| 威远镖局 | 原版商队和护送契约（`escort_caravan_contract` 已核实存在） |

## 5. 势力数量预算

硬限制：原版引擎战斗内势力 ID 到 64 会出错（见方案 M10）。

- 大纲新增：5 个起源势力 + 10 个门派 + 朝廷，约 16 个。
- 原版占用：每个城镇一个势力，加上贵族、城邦、各类敌人。总数我估计在 35–40，城镇数量凭记忆，没查到确切值。
- 结论：全面替换时原版的兽人、地精、亡灵等势力让出位置，放得下。两个条件：城镇总数不比原版多太多；门派的分舵不单独占势力。
- 不替换、只叠加时会逼近上限。

## 6. 地理分区

大纲要中原、江南、巴蜀南疆、西北四个方位固定的大区。原版地图只有南北分带：北雪、南漠（已核实，地形脚本按纬度和雪线判断）。

| 做法 | 效果 | 对应方案的级别 |
| --- | --- | --- |
| 按地形绑定门派驻地：沼泽给五毒、山地给剑派、森林给唐门和山寨、沙漠给魔教、雪原给密宗、平原给少林和世家 | 有地域感，但方位随机，大漠在南不在西北 | L2，用城镇类型的 `isSuitable(_terrain)`（已核实） |
| 重写地形生成，固定四个大区的方位 | 完全符合大纲 | L3(b)，工作量大 |

建议阶段三先做地形绑定，固定方位作为之后的可选项。

## 7. 三阶段 MVP 和方案里程碑的对应

| 大纲 | 对应方案 | 调整建议 |
| --- | --- | --- |
| 阶段一：1 起源 + 剑刀棍 + 内力与架势 + 少量贴图 | P0 + P1 | 保留 P0 技术验证。P1 把"一个完整门派"换成"三种兵器的招式 + 架势条"。起源建议用威远镖局，原版护送契约可直接用 |
| 阶段二：10–15 本秘籍、闭关、走火入魔、接镖循环 | P3 | 一致 |
| 阶段三：地貌、命名、五大势力、奇遇 | P4–P5 | 十个门派不在大纲的三个阶段里，是最大的一块内容量 |

十个门派的节奏建议：每个门派等于一套招式、一批敌人、一批 sprite、若干 AI 行为。先把三个差异最大的做完整（例如一个剑派、一个棍阵、一个暗器或用毒），验证"加门派不改框架"。其余的先只做成敌人兵种表，之后再逐个升级为可招募、可拜师。

## 8. 公开发布带来的两个问题

1. **名称。** 大纲里这些名字出自金庸或古龙作品，公开发布前要换成原创：日月神教、血刀门、五毒教、神龙教、慕容、吸星大法、天魔解体大法、打狗棒法、九花玉露丸、暴雨梨花针、百晓生和《兵器谱》。少林、武当、峨眉、华山、丐帮、唐门是真实存在或通用的名称，可以用。大纲自己的"残剑门、靖夜司、威远镖局"这类原创名是对的方向。
2. **以后做独立游戏能带走什么。** 文本、设定、原创美术、数值设计能带走；依赖 BB 的代码带不走；以原版 sprite 为底改绘的美术也带不走。如果独立游戏是真实目标，美术从第一天起就不要以原版素材为底。

## 9. 需要用户决定

1. 内力：疲劳换皮（B），还是独立资源（A）？
2. 架势条：叠在护甲之上，还是基本取代护甲？是否接受全部武器和敌人数值重定？
3. 确认全面替换原版世界？是否同意把武侠势力套在原版势力类上？
4. 女性角色做不做？
5. 十个门派的节奏：先完整做三个，其余先做成敌人？
6. 地理分区：先按地形绑定，还是一开始就要固定方位？
7. 是否引入 Modular Vanilla（做架势时更省事）？
8. 之前没答的：中文运行环境、是否有 Windows 开发机。
