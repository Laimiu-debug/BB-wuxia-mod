# BB-wuxia-mod 仓库评审

评审日期：2026-11-18（Asia/Hong_Kong）。对象：https://github.com/Laimiu-debug/BB-wuxia-mod（`main` @ `c1206bcc`）。

对照材料：
- [武侠mod设计方案](/cursor/stores/bc-b8a1a0a3-bf95-43a8-8cbc-f15d2d16db06/docs/wuxia-mod-design.md)
- [大纲对照报告](/cursor/stores/bc-b8a1a0a3-bf95-43a8-8cbc-f15d2d16db06/internal/wuxia-outline-reconciliation.md)

## 1. 仓库现状

只有一次提交「初始化武侠 Mod 设计资料和百科」，三个文件，没有 `.nut` 脚本、没有 mod 目录结构、没有 README。

| 文件 | 作用 | 体量 |
| --- | --- | --- |
| `武侠百科.html` | 自包含武侠设计百科：把 BBMOD 原版 2063 条词条映射到武侠命名，内嵌 158 个系统、222 篇武侠词条、9 个增设项、10 个设计议题，还有成长/交手推演 | ~1.1 MB |
| `jianghu-systems.html` | 「一局江湖的系统关系」交互图：九个模块的起因→后果，以及一趟药镖三种结局推演 | ~18 KB |
| `bbmod-wiki.html` | BBMOD 原版百科首页快照，作对照入口 | ~9 KB |

结论：还在**设计讨论阶段**，而且讨论工具已经比多数 BB mod 起步时扎实；真正的代码仓库还没开始。

## 2. 仓库里已经定下来的方向（比我们方案更新）

从百科 JSON 里直接读出：

1. **内力 = 疲劳替换**（`fatigue`，`rel: 替换`，增设项 `inner` 标「已选方向」）。这和用户六模块大纲一致，和我们方案第 2 节「独立资源」冲突；**以仓库为准**。
2. **全面换皮映射**：亡灵→古墓傀儡、兽人→山寨战帮、地精→奇门伏兵、危机全替换。等于选了「最终全面替换原版世界」。
3. **特长→武学专长、技能→招式**都是替换；修习路径强调「亲历难题 → 回师验证 → 突破」，不是纯升级点树。
4. **架势是否单列仍待议**（议题 `exchange`）：起手/拆招/破架有试稿，但「架势是否单列、破绽数值」没锁。
5. **队伍分工、护撤、换班**已经写成大量具体招式词条（临机换班、撤路留尾、雁签行息等），这是仓库比大纲和我们方案都更细的地方。

## 3. 哪里做得好

- **先对照原版再发明**：158 个系统逐条标「替换 / 改编 / 沿用 / 拆分 / 并入」，以后写代码时知道哪些能复用原版脚本。
- **系统关系图是正确的产品思维**：用一趟药镖把世界、差事、交手、伤养、名器、声名串起来，比孤立列功能清单强得多。
- **增设与议题分层清楚**：已选方向（内功、队伍分工）和后议项（通缉易容、黑市）分开，不会一上来全做。
- **招式写法像可实现规格**：锁气时点、取消返还、掩护丢失中断，比「内力消耗 XX」这种空描述更接近 BB 的 skill 事件模型。

## 4. 问题和更好的思路（按优先级）

### P0：把「已定」从百科里抽成单一真相源

现在已定决策埋在 1 MB HTML 的 JSON 里，方案文档、大纲、百科三处会漂。建议在仓库根加：

- `README.md`：项目一句话、运行/阅读方式、当前阶段
- `docs/decisions.md`：已拍板清单（内力=疲劳、全面替换、要求全 DLC、发布目标等）
- `docs/open-questions.md`：未定项，每条一个建议
- 把我们写的 `wuxia-mod-design.md` 放进 `docs/`，并改第 2 节对齐「内力=疲劳」

可上传的干净副本已放在 [for-github-upload](/cursor/stores/bc-b8a1a0a3-bf95-43a8-8cbc-f15d2d16db06/docs/for-github-upload/)。

### P0：锁定三个战斗核心，其余先冻结

仓库自己也承认架势未定。建议立刻定：

1. 内力：疲劳换皮（已定，写入 decisions）
2. 架势：第一阶段**不单列**；用现有「守势 / 准备 / 破绽」状态效果做简化版，数值验证后再考虑士气条换皮成架势条
3. 招式克制链：第一阶段只做「蓄势可被打断」，不做完整石头剪刀布

理由：同时做双资源重构 + 克制链 + 全世界换皮，第一年也难出可玩版。百科里护撤/换班那一套已经够做出差异化手感。

### P1：百科很好，但不要继续堆词条当进度

222 篇武侠词条里大量是「候选」。下一阶段应反过来：选定 **一个开局 + 一个门派原型 + 剑/枪各一套基础招式 + 四种敌人**，把对应词条从 candidate 升成「可实现规格」，其余词条冻结。

建议第一个门派不要用金庸名（版权）：用百科里已有的「威远护撤课 / 名山剑派」路线，做一个**护卫与换班**主题的镖局或剑派，正好吃掉你们写得最细的那批招式。

### P1：仓库结构要开始像 mod

讨论阶段也可以先建空壳，避免以后从 HTML 往外抠：

```
mod_wx/
  scripts/  # .nut 将来放这里
  ui/
  gfx/
docs/
tools/      # 从 武侠百科.html 导出 JSON 的脚本
```

`武侠百科.html` 的数据层（第一个 `<script>` 里的 JSON）最好拆成 `docs/data/book.json`，HTML 只做阅读器；否则每次改设计都要在巨文件里找。

### P2：和我们方案要对齐的技术债（百科几乎没写）

这些在设计方案里有、仓库里几乎空白，开工前要补进 decisions：

- 依赖：Modern Hooks + MSU + Nested Tooltips + DPF（四个，不是两个）
- 中文大地图：bb-launcher / Modern Engine / 拼音三选一
- DPF 改存档格式 → 必须新开档
- 势力 ID 上限 64；女性角色原版无素材
- 公开发布时，金庸/古龙专有名要换成原创

### P2：`jianghu-systems.html` 值得保留，并接到百科

系统关系图是最好的「给合作者看一眼就懂」的东西。建议在百科首页链过去，并在药镖三种结局旁标注「对应要写的契约/事件脚本名」。

## 5. 总评

方向对，深度够，工具也像样；主要风险不是「想得不够」，而是**设计资产已经多于可执行范围**。下一步价值最高的不是再写一百条词条，而是：

1. 把已定决策写成 `docs/decisions.md`
2. 冻结架势单列与完整克制链
3. 选定第一可玩切片（内力疲劳换皮 + 护撤主题门派 + 少量敌人）
4. 建 mod 空壳并开始第一个 `.nut` 技能
